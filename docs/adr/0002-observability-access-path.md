# ADR-0002: 에이전트의 관측 데이터 접근 경로 — Prometheus/Loki 직접 조회

- 상태: 승인됨
- 날짜: 2026-07-16

## 맥락

모니터링·분석 에이전트는 Prometheus(메트릭)와 Loki(로그)를 조회해야 한다 ([scenarios.md](../scenarios.md) ADR-0002 예약). 접근 경로 선택지는 두 가지다.

1. **직접 조회**: agent-service 가 compose 내부 DNS 로 `prometheus:9090` / `loki:3100` HTTP API 를 직접 호출
2. **control-plane 경유**: control-plane 이 관측 프록시 API 를 제공하고 에이전트는 그것만 호출

에이전트 도구(prometheus_tools, loki_tools)의 base URL 이 이 결정에 종속되므로 에이전트 구현 전에 확정이 필요하다. 제약 조건: 모니터링 에이전트는 "LLM 이 스스로 PromQL 을 작성해 조회"하는 설계라 쿼리 표현력을 제한하면 안 되고, control-plane 은 현재 미구현 상태다.

## 결정

**관측 데이터(읽기)는 직접 조회를 채택한다.** 판단 기준은 위험도 기반 분리 원칙 — **읽기는 직접, 상태를 바꾸는 조치는 통제 지점 경유** — 이다. 관측 조회는 읽기 전용이라 잘못돼도 피해가 제한적이고, control-plane 경유가 주는 이점(감사 단일화·자격증명 중앙화·토폴로지 추상화)은 위험한 작업에서 가치가 크다. 조치 실행 경로는 이 결정의 적용 범위 밖이며 ADR-0005 에서 별도 결정한다(화이트리스트 + human-in-the-loop 승인 원칙 유지).

## 검토한 대안

| 대안 | 장점 | 단점 | 기각 사유 |
|------|------|------|-----------|
| control-plane 경유 | 접근 감사·통제 단일 지점, 자격증명 중앙화, 에이전트에서 인프라 토폴로지 은닉 | 프록시 API 선행 구현 필요(당시 범위 초과), 조회마다 hop 추가, PromQL/LogQL 표현력을 프록시 뒤로 숨기면 "에이전트가 쿼리를 작성"하는 설계와 충돌 | 읽기 전용 + 무인증 내부 네트워크인 현 단계에서 이점 대비 비용 과다. 통제가 필요한 조치 실행은 ADR-0005 가 담당 |

## 결과

- 쉬워지는 것: 에이전트 도구가 표준 Prometheus/Loki HTTP API 를 그대로 사용 — 문서·예제 풍부, 디버깅 시 curl 로 동일 쿼리 재현 가능. control-plane 없이 에이전트 구현 진행 가능.
- 어려워지는 것: 관측 접근에 대한 감사 기록이 없음(에이전트 자체 로깅에 의존). 인증 있는 외부 관측 스택으로 옮기면 도구에 자격증명 처리 추가 필요.
- 되돌리기: 도구의 base URL 을 control-plane 프록시로 바꾸면 됨 — 도구 인터페이스(PromQL in, JSON out)를 유지하면 에이전트 코드 불변. 멀티 클러스터·접근 통제 요구가 생기는 시점에 재검토.
