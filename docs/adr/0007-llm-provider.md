# ADR-0007: LLM 프로바이더/모델 선정 — Anthropic Claude Sonnet 5

- 상태: 승인됨
- 날짜: 2026-07-16

## 맥락

멀티 에이전트(모니터링/분석/실행 + Supervisor)의 LLM 프로바이더와 모델이 미결이었다 ([scenarios.md](../scenarios.md) ADR-0007 예약). 에이전트 구현(2주차)의 의존성 패키지(langchain-anthropic vs langchain-openai)와 모델명이 이 결정에 종속된다.

워크로드 특성: 인시던트 1건당 LLM 호출 ~10회 내외(라우팅 일부 + 에이전트별 ReAct 루프), **tool calling 품질이 핵심**(PromQL/LogQL 작성, 구조화 출력), 실 사용자 트래픽 없는 학습·데모 규모라 절대 비용은 작다.

가격 비교 (2026-07 기준, 1M 토큰 입력/출력):

| 모델 | 입력 | 출력 |
|------|------|------|
| Claude Haiku 4.5 | $1.00 | $5.00 |
| **Claude Sonnet 5** | $3.00 (인트로 $2.00, ~2026-08-31) | $15.00 (인트로 $10.00) |
| Claude Opus 4.8 | $5.00 | $25.00 |
| GPT-5.6 Luna / Terra / Sol | $1.00 / $2.50 / $5.00 | $6.00 / $15.00 / $30.00 |

## 결정

**Anthropic Claude Sonnet 5 (`claude-sonnet-5`) 를 전 에이전트 공통 모델로 채택한다.** 의존성은 `langchain-anthropic`(1.x). tool calling·에이전트 워크로드 품질이 상위 티어이면서 인트로 가격($2/$10)으로는 OpenAI 동급(Terra $2.5/$15)보다 저렴하고, Claude Code 와 같은 생태계라 프롬프트·도구 설계 경험이 이전된다. 모델명은 설정(`config/`)으로 주입해 에이전트별 차등(예: 모니터링=Haiku)이 필요해지면 코드 변경 없이 전환한다.

## 검토한 대안

| 대안 | 장점 | 단점 | 기각 사유 |
|------|------|------|-----------|
| Claude Haiku 4.5 | 최저가($1/$5) | 분석 에이전트의 근본원인 추론·가설 검증 품질이 한 단계 아래 | 데모 규모라 비용 차이가 미미한데 품질만 잃음. 추후 역할별 차등의 후보로 보류 |
| OpenAI GPT-5.6 Terra (원안) | 5월 프로젝트 경험 재활용, langchain-openai 익숙 | 인트로 기간 Sonnet 5 대비 비싸고 tool calling 품질 이점 없음 | LangChain 추상화 위에서는 프로바이더 전환 비용이 낮아 "경험 재활용" 이점이 작음 |
| 역할별 혼합 (모니터링=Haiku, 분석=Sonnet) | 비용 최적 | 초기 복잡도 증가, 품질 문제 시 원인 분리 어려움 | 단일 모델로 기준선을 먼저 만들고, 비용·품질 데이터(Langfuse) 확보 후 차등 검토 |

## 결과

- 쉬워지는 것: 전 에이전트 동일 모델이라 프롬프트 튜닝·품질 비교 기준선이 단순. 인트로 가격 기간(8월 말까지) 동안 비용 부담 최소.
- 어려워지는 것: Anthropic API 키 관리 필요(.env, git 미추적). 인트로 종료 후 $3/$15 로 상승 — Langfuse 비용 데이터로 그 시점에 역할별 차등(Haiku 혼합) 재검토.
- 되돌리기: LangChain 의 모델 추상화 덕에 `init_chat_model` 수준에서 프로바이더 전환 가능 — 설정값과 의존성 패키지 교체로 충분. 프롬프트 재튜닝 비용은 발생.

## 추가 사항 (2026-07-16): 프로바이더 전환 가능 설계

기본 모델(Claude Sonnet 5)은 유지하되, **설정을 통해 OpenAI GPT-5.6 Terra 로 전환 가능한 구조**를 채택한다.

- 설정 형식: `LLM_MODEL="프로바이더:모델명"` (예: `anthropic:claude-sonnet-5`, `openai:gpt-5.6-terra`) — LangChain 의 `init_chat_model` 이 프로바이더를 해석하므로 에이전트 코드는 프로바이더를 모른다.
- 의존성: `langchain-anthropic` + `langchain-openai` 둘 다 포함. API 키는 활성 프로바이더의 것만 검증.
- **지원 수준 구분**: 프롬프트·품질의 기준(primary)은 Sonnet 5 하나로 유지하고, OpenAI 는 전환 실험용 best-effort — "듀얼 지원 매트릭스"(양쪽 상시 테스트)는 비목표. 프로바이더 고유 파라미터는 공통 분모만 사용하거나 설정 계층에 격리한다.
- 부수 효과: 같은 인시던트를 두 모델로 실행해 Langfuse 에서 비용·tool calling 궤적을 비교 가능 — 본문 "역할별 차등 재검토"에 필요한 데이터의 수집 수단.

## 추가 사항 (2026-08-17): 역할별 모델 차등의 실현 — llm-gateway 라우팅 (6주차)

본문이 보류했던 "역할별 혼합"이 **llm-gateway 의 태스크 라우팅**([ADR-0015](0015-llm-gateway.md))으로 실현됐다. 결정 지점이 클라이언트 설정에서 게이트웨이 정책(yml 외부화)으로 이동:

- 라우팅 규칙: `monitoring-summary → claude-haiku-4-5` (저비용 — 관측 데이터 요약은 추론 부담 낮음) / `root-cause-analysis → claude-sonnet-5` (본문 근거 유지 — 가설 검증·tool calling 품질) / 미등록·기본 → `claude-sonnet-5` (기존 동작 등가).
- 에이전트는 `X-Task-Type` 헤더만 보낸다 — 본문의 "에이전트 코드는 프로바이더를 모른다"가 "모델도 모른다"로 확장. 설정도 의미 단위로 분리: `LLM_CLIENT=openai` 는 게이트웨이의 OpenAI 호환 와이어 프로토콜(모델의 프로바이더 아님), `LLM_DEFAULT_MODEL=default` 는 **게이트웨이 별칭**(실모델명 아님 — 게이트웨이가 default 라우팅 규칙으로 해석) — 에이전트 설정에 프로바이더 모델명이 등장하지 않는다 (2026-07-16 추가 사항의 `LLM_MODEL="프로바이더:모델"` 형식을 대체).
- 본문 기각 사유였던 "품질 문제 시 원인 분리 어려움"의 대응: 게이트웨이 메트릭(`gateway_requests_total{task, model}`)이 태스크-모델 대응을 상시 기록 — 문제 시 규칙 1줄 롤백으로 단일 모델 복귀.
- `langchain-anthropic` 의존성 제거 — 직접 호출 경로 소멸 (프로바이더 실키는 게이트웨이만 보유). 2026-07-16 추가 사항의 "전환 가능 설계"는 게이트웨이 라우팅 규칙으로 승계.
