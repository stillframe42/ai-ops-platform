# ADR-0008: Supervisor 라우팅 — 규칙 우선 하이브리드

- 상태: 승인됨
- 날짜: 2026-07-19

## 맥락

Supervisor 는 상태를 보고 다음 에이전트(monitor/analysis/action)를 결정한다 ([scenarios.md](../scenarios.md) ADR-0008 예약). 라우팅 방식 선택지는 매 결정을 LLM 에 맡기는 것부터 전부 규칙으로 두는 것까지 스펙트럼이 있다. 제약 조건: 모든 에이전트가 Supervisor 로 복귀하는 허브 구조상 진입 횟수 = 실행 에이전트 수 + 1(종료 판정) — 인시던트 1건당 3회(P3 조기 종료)~4회(전체 경로), 재분석 시 그 이상 진입하므로 라우팅 비용이 그대로 곱해지고, 라우팅이 비결정적이면 테스트(회귀망)와 장애 대응 예측 가능성이 무너진다. 반면 "낮은 확신의 분석 보고서로 조치 계획을 만들어도 되는가"는 상태 필드만으로 가를 수 없다.

## 결정

**전이를 두 종류로 나눈다 — 명확한 전이는 규칙, 모호한 판단만 LLM.** 상태만 보면 결정되는 전이(모니터링 없음 → monitor, 분석 없음 → analysis, P3 → 종료, 조치 계획 완료 → 종료, P1·P2 + confidence ≥ 0.6 → action)는 규칙으로 처리해 비용 0 에 결정적으로 유지한다. LLM 은 단 하나의 모호 구간 — P1·P2 인데 confidence < 0.6 일 때 재분석(analysis)과 조치 진행(action) 중 택일 — 에만 개입하고, 판단 근거를 messages 에 남긴다. LLM 개입은 재분석 순환을 만들 수 있으므로 무한 루프 방지를 결정의 일부로 포함한다: Supervisor 방문 카운터 5회 초과 시 강제 종료 + 에스컬레이션, 그래프 `recursion_limit` 을 이중 방어로 설정.

## 검토한 대안

| 대안 | 장점 | 단점 | 기각 사유 |
|------|------|------|-----------|
| 전면 LLM 라우팅 (Supervisor 가 매번 LLM 호출) | 상태 스키마에 없는 맥락까지 반영한 유연한 판단, 라우팅 로직 코드 최소화 | 인시던트당 4회 이상의 LLM 호출 비용, 비결정적 — 같은 상태에서 다른 경로 가능, 라우팅 회귀 테스트가 스텁 없이 불가 | 전이 대부분이 "다음 단계가 자명"한 순차 흐름이라 LLM 의 유연성이 쓰일 곳이 없음 — 비용·비결정성만 남는다 |
| 전면 규칙 라우팅 (LLM 없음) | 비용 0, 완전 결정적, 테스트 단순 | 모호 구간을 임계값 하나로 강제 결정 — "confidence 0.55 는 무조건 재분석" 같은 규칙은 근거 없는 이분법 | 낮은 확신 보고서의 처리(재분석 가치 vs 대응 지연)는 보고서 내용을 읽어야 하는 판단 — 규칙으로 두면 임계값 튜닝 문제로 변질된다 |

## 결과

- 쉬워지는 것: 라우팅 회귀 테스트가 규칙 경로에서 LLM 스텁 없이 성립 (규칙 경로에서 LLM 라우터가 호출되면 테스트가 실패하도록 강제 — 비용 유출 감지 겸용). 인시던트당 라우팅 LLM 비용은 최악에도 재분석 횟수만큼만.
- 어려워지는 것: 모호 구간 경계(confidence 0.6)가 새 튜닝 포인트가 됨. LLM 라우팅 판단 품질은 실측으로만 검증 가능.
- 되돌리기: 모호 구간 분기 하나를 제거하면 전면 규칙으로, supervisor_node 를 LLM 호출로 바꾸면 전면 LLM 으로 — 방문 카운터·recursion_limit 은 어느 쪽에서도 유지할 가치가 있다.
